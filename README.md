# Такт — командный трекер задач

Деловой веб-трекер задач малой команды (2–5 человек): проекты, канбан-доска
(«Бэклог / В работе / На проверке / Готово»), приоритеты, исполнители,
дедлайны и комментарии. Вход по логину и паролю, две роли:
**админ** (управление пользователями и проектами, полные права)
и **программист** (работа с задачами и комментариями).

Учебный кейс №3 курса «Фриланс 2026» (урок FGIp07 Кейс 4),
по реальному заказу FL.ru №1634681 «Установи систему контроля версий
и трекер задач» (упрощено: автономный трекер, без интеграции в сайт заказчика;
подробности — в `info/agents.md`).

## Стек

- **Node.js** (LTS, проверено на 22+), **Express 5** — сервер и API
- **SQLite** через `better-sqlite3` — данные на сервере (файл `db/task.db` создаётся автоматически)
- **bcryptjs** — пароли хранятся только в виде хэшей
- **express-session** — сессии в cookie (`takt.sid`)
- **Ванильный HTML/CSS/JS** на клиенте — без фреймворков и сборщиков
- Шрифт IBM Plex Sans (Google Fonts) с системным fallback — не ломается без сети

## Локальный запуск

Нужен Node.js LTS (проверялось на 22+). В каталоге проекта:

```bash
npm install
npm start
```

Откройте `http://localhost:3003` — сервер слушает `0.0.0.0:3003`.

При первом старте база создаётся автоматически и наполняется демо-данными:
1 проект «Сайт CakePHP — поддержка», 10 задач по всем статусам и приоритетам,
4 комментария. Повторные запуски данные не затирают и не дублируют.

## Деплой на Railway (пошагово)

Данные лежат в SQLite-файле, поэтому систему можно поднять без внешней БД.
Railway на деплое сам выполнит `npm install` и создаст базу с демо-данными.

1. **Загрузите проект на GitHub** (публичный или приватный репозиторий):
   ```bash
   git init            # если ещё не сделано (в этом проекте уже есть репозиторий)
   git add -A
   git commit -m "итерация"
   git remote add origin https://github.com/<ваш_логин>/takt.git
   git push -u origin main
   ```
2. Зайдите на **railway.com** → «New Project» → **Deploy from GitHub repo** →
   выберите репозиторий `takt`.
3. Railway распознает Node.js-проект по `package.json`. Если конфиг не подхватился —
   в «Settings → Build/Deploy» проверьте, что указан Builder **Nixpacks**
   (в репозитории есть файл `railway.json`) и команда запуска `npm start`.
4. В **Variables** добавьте переменную окружения:
   - `SESSION_SECRET` — любая длинная случайная строка (обязательно для продакшена);
   - при желании `PORT` необязателен: Railway подставит свой, код читает `process.env.PORT`.
5. Дождитесь первого деплоя. Если сборка `better-sqlite3` на стороне Railway
   упадёт — View Logs → Create Pull Request (Railway сам предложит правку Nixpacks)
   и после Merge автоматом переедет Redeploy.
6. **Settings → Networking → Generate Domain** — получите публичную ссылку
   на приложение.
7. Проверка: откройте ссылку, войдите `boss1` / `Boss#2026`, убедитесь,
   что демо-проект с задачами на месте (сид отрабатывает при первом старте).

> ⚠️ На проекте в бесплатном тарифе Railway файловая система эфемерна:
> при очередном редеплое SQLite-файл создаётся заново из сидов, а данные,
> внесённые после предыдущего деплоя, сбрасываются. Для учебного MVP этого
> достаточно; если нужны сохранные данные — подключите Railway Volume
> (Settings → Volumes) и храните `db/` на нём.

## Что сознательно упрощено (в рамках MVP)

- Нет самостоятельной регистрации и восстановления пароля — только админ.
- Нет вложений файлов, уведомлений (e-mail/пуш) и истории изменений.
- Перемещение задач — кнопками «←/→», drag&drop не делается.
- Сессии в памяти процесса: при рестарте сервера всем нужно войти заново.
- SQLite — один файл, без миграционного инструмента; схема через CREATE TABLE IF NOT EXISTS.

## Проверка после деплоя (минимальный сценарий)

1. Вход `boss1`/`Boss#2026` → список проектов, счётчики по статусам.
2. Открыть доску → задача «Баг: рассылка падает с ошибкой 500» — критический,
   просрочена (левая красная полоса).
3. Создать задачу → выдвинуть по статусам кнопками «→» → прокомментировать.
4. «Пользователи» → создать учётку → выйти → войти новой учёткой.
5. Выйти → вход `dev1`/`Dev#2026` → убедиться: «Пользователи» и «Создать проект» недоступны.
