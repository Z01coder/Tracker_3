## Зафиксированные решения (согласованы со студентом)

| Решение | Значение |
|---|---|
| Стек | Node.js LTS + Express + SQLite (better-sqlite3; при проблемах сборки — `node:sqlite`) + ванильный HTML/CSS/JS, без фреймворков и сборщиков |
| Порт | 3003, слушать на `0.0.0.0` |
| Авторизация | `express-session` (сессия в cookie) + `bcryptjs` для хэширования паролей |
| Роли | админ (управление пользователями и проектами, полные права), программист (работа с задачами) — ровно 5 демо-аккаунтов: 2 админа + 3 программиста |
| Канбан | 4 колонки: «Бэклог / В работе / На проверке / Готово»; перемещение задач — **только кнопками** (drag&drop не делаем) |
| Демо-данные | 1 демо-проект с набором задач (исполнители, приоритеты, комментарии) сверх 5 сид-аккаунтов |
| Управление контроля | Значимые гейты: подтверждение ТЗ (этап 1) и приёмка после стилизации (этап 6); между ними — самостоятельная работа с короткими отчётами в чате после каждого этапа |
| Языки | интерфейс и комментарии в коде — русские; комментарии содержательные |
| Вне скоупа | чужой CakePHP-сайт, установка VCS у клиента, пуш на GitHub/Railway (студент сам), платные API |
| Запреты | не изменять `info\*` (кроме создаваемого `agents.md` и логотипа), `lesson.txt`, `workbook_extract.txt`, DOCX |

**Гейт ⛔:** дождаться подтверждения ТЗ студентом до начала этапа 2.

### Этап 2 — Каркас проекта ⬜
**Работы:**
- Структура папок (единообразно с другими трекерами): корень `Tracker_3\` — `server\` (код бэкенда), `public\` (статика), `db\` (файл SQLite), `README.md`.
- `package.json`, зависимости: `express`, `express-session`, `bcryptjs`, `better-sqlite3` (или fallback `node:sqlite`).
- Скелет Express-сервера, `/health`-заглушка, раздача статики, порт 3003 на `0.0.0.0`.
- `.gitignore` (node_modules, db-файл, tmp), `git init` + первый коммит.
**Результат / критерий:** `node server\index.js` поднимает сервер на http://localhost:3003; коммит сделан.

### Этап 3 — БД, сид-данные и авторизация ⬜
**Работы:**
- Схема SQLite: `users` (id, логин, имя, роль admin|programmer, хэш пароля), `projects`, `tasks` (статус, приоритет, исполнитель, дедлайн), `comments`; автосоздание и миграция при первом старте.
- Сиды: ровно 5 аккаунтов (2 админа + 3 программиста) с bcrypt-хэшами; 1 демо-проект с задачами по статусам/приоритетам с исполнителями и комментариями. Логины/пароли демо-аккаунтов — придумать и записать (появятся в README и agents.md).
- Сессии: `express-session` с `secret` (из переменной окружения с дефолтом для разработки) и cookie; middleware `requireAuth`, `requireAdmin`.
- Login/logout API, `GET /api/me`.
**Результат / критерий:** вход под демо-админом и демо-программистом работает (проверить логином с неверным паролем тоже), повторный старт сервера не дублирует сид-данные.

### Этап 4 — REST API ⬜
**Работы:**
- Проекты: CRUD (создание/редактирование/удаление — только админ; просмотр — все авторизованные).
- Задачи: CRUD внутри проекта, смена статуса, приоритет, исполнитель (выбор из пользователей), дедлайн; перемещение между колонками = запрос смены статуса.
- Комментарии: добавление и просмотр; редактирование/удаление — автор или админ.
- Пользователи (только админ): создание, редактирование, деактивация.
- Единая проверка прав на каждой ручке; корректные HTTP-коды; JSON-ошибки на русском.
**Результат / критерий:** все ручки проверены (Postman/curl/браузером) под админом и программистом; программист не может создавать проекты и пользователей, но работает с задачами и комментариями.

### Этап 5 — Фронтенд-функционал (без финишного стиля) ⬜
**Работы:**
- Экраны: вход; список проектов; канбан-доска проекта (4 колонки, кнопки перемещения статуса); карточка задачи (модалка/страница): поля, исполнитель, дедлайн, комментарии; админ-панель «Пользователи»; создание/редактирование проекта.
- Роли на фронте: админ-элементы скрыты/недоступны программисту.
- Демо-данные видны сразу после входа — первый запуск не пустой.
**Результат / критерий:** основной сценарий проходим мышкой без ошибок: вход → проект → доска → создать задачу → перевести по статусам → прокомментировать; под админом — создать пользователя и проект.

### Этап 6 — Стилизация и адаптивность ⬜
**Работы:**
- Применить мини-брендбук из agents.md: палитра, шрифт (системный стек или бесплатный Google Fonts с безопасным fallback), SVG-логотип в шапке.
- Деловой сдержанный стиль «ближе к Jira»: аккуратные карточки, статусы-метки цветовыми кодами, читаемая типографика.
- Адаптивность: desktop / tablet / mobile (колонки канбана на мобильном — горизонтальный скролл или переключение).
- Доступность не хуже базовой: контраст, фокусные состояния.
**Результат / критерий:** интерфейс соответствует брендбуку на трёх разрешениях (проверка глазами).
**Гейт ⛔:** показать результат студенту до финальной сдачи.

- Консоль браузера без ошибок; чинить найденные баги до чистого прогона.
- Проверка по критериям MVP из agents.md.
**Результат / критерий:** основной сценарий и сценарий прав проходят без ошибок; список проверенного — в финальном отчёте.
